## 배경

세특 점검 결과를 담당 교사에게 보내 확인을 요청했는데, 선생님들이 제대로 확인하지 않고
"처리 완료"를 무지성으로 눌러버리는 문제가 발생. 학교 선생님 대부분이 이 시스템을
처음 써보는 상황이라 안내 문구만으로는 부족하고, 강제성 있는 UX 가드가 필요하다고 판단.

## 완료된 작업

### 1. 처리완료 클릭 시 메모 입력 필수화

- 커밋: `17e3b5b` (origin/main에 push 완료)
- 파일: `apps/portal/src/pages/setuk/SetukCheckDetail.jsx`
- 내용: "처리완료(반드시 수정해야 하는 경우)" 버튼을 누를 때 메모가 비어 있으면
  `window.alert`로 경고 후 클릭(상태 변경) 자체를 취소.
- "이상없음"(오탐 확인) 버튼은 실제 나이스 수정이 아니므로 메모를 강제하지 않음.
- 메모 입력칸을 controlled component로 바꿔 blur 저장을 기다리지 않고도 방금 입력한
  값을 즉시 검증할 수 있게 함.

## 백로그 (미구현 — 다음주 학교 선생님들과 직접 논의 후 진행 여부/형태 결정 예정)

### 2. 학교 전체 점검 기간 잠금

- 관리자가 버튼 하나로 학교 전체(1·2학기 구분 없이 한 번에) `setukChecks`/`items`를
  더 이상 수정 못 하게 잠그는 기능.
- 설계안: `/schools/{schoolId}` 밑에 잠금 상태 문서 하나
  (예: `setukLock: { locked, lockedAt, lockedByName }`)를 두고, firestore.rules에
  기존 `isSetukSubjectTeacher` 같은 패턴으로 잠금 여부를 확인하는 함수를 추가.
- **왜 필요한가**: 지금은 언제든 처리완료·메모를 계속 바꿀 수 있어 "직전 데이터"라는
  기준 자체가 계속 흔들림. 이 잠금이 아래 3번 비교 기능의 깔끔한 스냅샷 기준점이 됨.

### 3. 재점검 시 직전 체크 대비 검증

- 새로 업로드된 세특 데이터와 직전 체크(같은 학급, `sourceFileCreatedAt` 기준
  가장 가까운 이전 것)를 비교.
- 이전에 `resolution: 'fixed'`(처리완료)였던 항목의 걸렸던 문구(`matched`)가 새
  원문에도 그대로 남아있으면 "아직 미수정으로 보임"을 안내.
- 단순 부분 문자열 포함 검사로 충분 — 파서가 이미 레코드를 과목 단위(`subjectName`)로
  쪼개놓아서 학기별 다운로드/학년 전체 다운로드 형식 차이는 문제가 안 됨(학년 전체
  다운로드는 1·2학기 구분 없이 합쳐지지만, 과목명이 명시적으로 표시되어 있어 과목
  단위 비교는 그대로 가능).
- 표현에 관한 결정: "재발"이라는 단어는 범죄를 연상시켜 부적절 — "확인 필요" 정도의
  중립적인 톤으로 안내할 것.

### 4. 관리자용 점검 현황 확인 — 웹 대시보드 + 마감 후에만 파일 다운로드 활성화

- 반별 상세 화면(`SetukCheckDetail.jsx`)엔 이미 처리완료/이상없음/미처리 집계가
  있으므로, 이를 전체 학급을 가로지르는 관리자 요약 화면(반별 완료율, 담당 교사별
  미처리 건수)으로 확장.
- 결과 파일 다운로드(`exportCheckResults`)는 애초에 "파일로 받기 싫어서" 웹 도구로
  만든 것이라 평소엔 필요 없음 — **2번 잠금 이후에만** 최종 기록/증빙용으로 다운로드
  버튼을 활성화하는 방향으로 논의됨(잠금 전엔 데이터가 계속 바뀌어서 파일 스냅샷이
  의미 없음).
